# 開發環境與搬家說明

這份文件寫給「換一台電腦開發」或「伺服器要搬家」的時候用。照著做就能從零接回來。
（只寫東西放在哪裡、怎麼設定；**金鑰、密碼本身不寫在這裡**，它們只存在各服務的後台。）

### Vercel 環境變數（在 Vercel 後台 → Settings → Environment Variables）

| 名稱 | 用途 | 必填 |
|---|---|---|
| `ABLY_API_KEY` | 備援連線的 Ably 金鑰 | 是 |
| `RT_TW_URL` | 換台北伺服器網址時才設；設成 `off` 會改用 `RT_CF_URL` | 否 |

| `RT_PREFER` | 設成 `ably` 會先用 Ably | 否 |
| `KV_REST_API_URL`／`KV_REST_API_TOKEN` | `api/hall` 讀球館資料用的 Redis（Vercel 自動接上） | 是 |

## 二、新電腦開發

需要安裝：Git、Node.js 22 以上、Python 3（開本機網站用）。要改角色模型才需要 Blender 4。

```bash
git clone https://github.com/yushiang891221/volleycourt.git
cd volleycourt
git checkout game-site
python -m http.server 5180
```

- 開 http://localhost:5180 是大廳（要 Google 登入）。
- 開 http://localhost:5180/gym.html?site=bs-shenjing&practice=1&dev 可以**不登入**直接進練習房（`&dev` 只在 localhost 有效，正式網站沒用）。
- 本機沒有 `api/`，所以多人連線、球館資料會改用備援，這是正常的；要測多人要推到 Vercel 預覽網址或正式網站。
- 跑全部自動檢查：`node tools/run-tests.cjs`。有「新失敗」就不要推上線。
- 換行一律用 LF（`.gitattributes` 已經設定好，Windows 也不會變成 CRLF）。

### Claude／Codex 的資料
- 工作單、Codex 執行腳本：`docs/codex工作單/`（`run_codex.ps1` 會自動找自己的位置，不用改路徑）。
- 待辦清單：`docs/tickets.md`。
- 架構規劃：`docs/架構-伺服器權威.md`。

## 三、台北伺服器

### 平常更新
在 repo 根目錄（Git Bash）：

```bash
bash server/rt/deploy.sh
```

它會檢查語法、上傳 `server/rt`、`server/shared`、`js/auth-config.js`，重新啟動服務，最後印出 `ok`。

需要的金鑰：`~/.ssh/volley_tw`（在開發用的電腦上）。換電腦時，用 `ssh-keygen -t ed25519 -f ~/.ssh/volley_tw` 產生新的，再用密碼登入伺服器，把 `~/.ssh/volley_tw.pub` 的內容加進伺服器的 `~/.ssh/authorized_keys`。

### 從零重建（換一台主機、換一家廠商）
1. 開一台 Ubuntu 24.04 以上、1 vCPU／2 GB 的機器（台灣機房），記下 IP。
2. 把金鑰裝上去（同上）。
3. 登入後安裝：`apt-get update && apt-get install -y nodejs npm caddy`，再建立服務帳號：`useradd --system --home /opt/volleycourt --shell /usr/sbin/nologin volley`。
4. 把 `server/rt/Caddyfile` 第一行的網址改成新 IP（格式 `1-2-3-4.sslip.io`，免費、不用買網域，Caddy 會自動申請 https 憑證）。`server/rt/deploy.sh` 裡的 `HOST` 也改成新 IP（或執行時設 `VOLLEY_HOST=root@新IP`）。
5. 執行 `bash server/rt/deploy.sh`。
6. 把 `api/rt-config.js` 裡的 `TW_DEFAULT` 改成新網址（或在 Vercel 設 `RT_TW_URL`），推上線。
7. 大廳資料存在伺服器的 `/var/lib/volleycourt/lobby.json`（只有房間公告和大廳聊天，丟掉也沒關係）。

伺服器上的位置：程式 `/opt/volleycourt`，服務名稱 `volleycourt-rt`（`systemctl status volleycourt-rt`、`journalctl -u volleycourt-rt`）。

## 四、Supabase（資料庫）

`supabase/` 裡的 SQL 照編號順序（001 → 016）在 Supabase 後台的 SQL Editor 執行過一次。新專案要全部依序執行；之後新增的 SQL 也照編號接下去。

## 五、上線流程

1. 在 `game-site` 分支改、提交。
2. `node tools/run-tests.cjs` 沒有新失敗。
3. 本機用 `&dev` 打開確認。
4. `git push origin game-site` 和 `git push origin game-site:main`，Vercel 會自動上線（約 1 分鐘）。
5. 有改 `server/rt` 的話，另外執行 `bash server/rt/deploy.sh`。
