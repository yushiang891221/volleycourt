# 匿名建議信箱部署

收件人固定為 `yushiang891221@gmail.com`（`server/shared/feedback-mail.cjs`）。玩家每週限送一次，成功收件即加 500 金幣；台灣時間週一 00:00 重置。信件不含玩家 ID、暱稱或 Email。內容表與週資格表沒有互相連結的欄位；這是應用層匿名，並非對資料庫管理員或基礎設施日誌的不可追蹤保證。

## 開通步驟

1. 在 Supabase 專案的 SQL Editor 執行 `supabase/025_anonymous_feedback.sql`。可重複執行；沿用現有 `player_progress` 金幣欄位。
2. 建立 Resend 帳號與寄信 API key，正式使用請設定已驗證的寄件網域。
3. 在 Vercel 的 **volleycourts → Settings → Environment Variables** 設定 Production 環境變數：

| 名稱 | 值 |
| --- | --- |
| `RESEND_API_KEY` | Resend 寄信金鑰 |
| `FEEDBACK_FROM` | 例如 `Play One <feedback@你的已驗證網域>` |
| `SUPABASE_SERVICE_ROLE_KEY` | 遊戲 Supabase 專案的 service role 金鑰，只放伺服器 |
| `CRON_SECRET` | 隨機產生至少 32 字元的秘密值，保護補寄端點 |

金鑰不要放在前端、Git 或聊天中。Gmail 只是收件地址，不需要提供 Gmail 密碼。

4. 發布這次程式並重新部署，讓環境變數生效。
5. 使用測試帳號送出建議，確認資料庫一封信、金幣只增加 500、Gmail 收到通知；重複送出與換裝置均不得重領。

尚未設定寄信環境變數時，送出 API 會回報信箱未開通，不透過此 API 收件或發獎。資料庫權限與每週限領仍由 RPC 自行驗證。

## 收信與補寄

平時直接在 Gmail 看主旨 **Play One｜收到一封匿名建議**。寄信服務接受請求不代表 Gmail 一定已送達，必要時看垃圾郵件匣與 Resend 投遞狀態。

收件及發獎是同一筆資料庫交易。寄信暫時失敗，建議仍保存在 Supabase → Table Editor → `anonymous_feedback`；`emailed_at` 空白表示等待寄出。該表沒有對一般玩家開放讀取權限。

Vercel 每天 UTC 01:00（台灣上午 09:00，實際觸發時間依方案）呼叫受 `CRON_SECRET` 保護的 `/api/feedback`，每批最多補寄 10 封。大量待寄可由管理員帶 Bearer cron secret 手動呼叫此 GET 端點，不要把 secret 放網址。寄信錯誤不回滾玩家的獎勵。

每封使用固定建議 UUID 作為 Resend idempotency key；其去重期限是 24 小時。極端情況下寄成功但回寫失敗，超過期限補寄仍可能有同編號重複信，金幣不會重發。

## 驗證

- `node tests/verify-feedback.cjs`：API 驗證、寄信失敗保留、固定收件人、重試回覆（不發真信）。
- `node tests/feedback-db.cjs <@electric-sql/pglite 的安裝路徑>`：執行真實 SQL，測試一次 500、重複請求、跨週、台灣時區、回滾與存取權限。
- `node tests/feedback-ui.cjs <playwright 的安裝路徑>`：隔離瀏覽器、假帳號與 API；不存取正式帳號或寄信。

參考：[Resend 寄信 API](https://resend.com/docs/api-reference/emails/send-email)、[Resend 測試網域限制](https://resend.com/docs/knowledge-base/403-error-resend-dev-domain)、[Vercel Cron 管理](https://vercel.com/docs/cron-jobs/manage-cron-jobs)。
