## 整合版本的實作範圍

以下均指尚未套用的整合版本，不能視為正式頁面已生效。

### 進房畫面

原因為原頁面以 `data-mode="plan"` 初始化，待 `generateFromSite()` 結束才 `setMode('walk')`。

整合版本在真正的 body 最前面加入全螢幕深色載入畫面，顯示「進入球館中…」及階段進度 5／20／75／100%。這是階段進度，不是假裝知道下載百分比。平面圖容器另以關鍵 CSS 永久隱藏。完成走動模式切換並實際呼叫第一個 3D frame 後，才淡出遮罩。失敗時保留遮罩及回大廳入口。

### 右上角與房間資訊

右上角改為房主設定、設定、回大廳；房主設定僅在身分確定且為房主時顯示。移除多人連線面板與原本各顆設定按鈕、看平面圖／離開導覽。房號、人數、連線狀態與可展開名單放在左上小資訊列，避免大型面板擋住遊戲。

大廳開房網址新增 `host=1`，代碼加入不加。名字取自共用設定，既有 `?room=` 自動進房流程保留。練習模式自己是房主。

### 房主球速

新增獨立的 `room-settings` 訊息，使用既有 transport 的 publish／subscribe；沒有修改 Ably、Cloudflare、BroadcastChannel 原有訊息格式，也沒有修改 rt-worker。

房主廣播加入順序與球速；晚加入取得同一份狀態。房主離開後，依已同步的加入順序接手，保留球速。非房主不能透過控制器更改球速，且已知房主以外的規則快照會被忽略。後來帶著 host=1 加入的人不會搶走既有房主。

舊比賽訊息中的 ts 欄位仍保留格式，但接收端改由 room-settings 決定球速，以免「比賽模擬主機」覆蓋「房間房主」的設定。這是最小可用的瀏覽器房主機制，尚未涵蓋 WEB-003 的完整房間流程、伺服器權威或所有斷線重連情境。

### 個人設定

大廳底部系統設定與遊戲頁共用同一個 settings.js／settings.css 面板：

- 遊戲：接球輔助、視角輔助、落點圈、按鍵提示、比賽／陪練預設第三人稱、隊友耐力圈。六項都接到網頁既有功能。
- 畫面：實際全螢幕／視窗切換、原有高／省電兩段畫質、60～100 度 FOV。
- 控制：滑鼠靈敏度、實際網頁按鍵綁定與重複互換、還原按鍵、三種舉球選單左右對調。
- 音效：主音量與靜音，接到既有 Web Audio 輸出增益及大廳留言提示音。
- 其他：暱稱驗證 2～12 個字元，與 vb.mp.name 同步；還原設定保留暱稱身分。

設定統一存入 `vb.settings` JSON；`vb.mp.name` 保留作相容鍵，讀寫集中在 settings.js。舊 vb.quality、vb.fov、vb.sfx 僅用於首次遷移。球速屬房間狀態，不放個人設定，不跨分頁透過 localStorage 擅自改房間規則。

按鍵含 WASD、方向鍵別名、Shift、E、V／Q 接球別名、空白、B、T、P、F、1～5、方括號，以及網頁現有羽球／匹克球 J／K／L。保留預設操作，沒有照搬 Godot 的 C、Ctrl、R、Enter、F3 等不存在的排球操作。滑鼠左右鍵與滾輪保留原用途。

舉球左右對調只更換選項的位置，原本未選擇時的預設球路保留。滑鼠靈敏度同時接到鎖定滑鼠與拖曳轉頭的既有係數。

### Esc 衝突處理

原本 Esc 用於切換游標／轉頭，另負責關閉回放、球拍模式選單、場景電腦與媒體視窗。

整合版本保留上述視窗關閉優先順序。一般遊戲狀態按 Esc 開啟設定，關閉後點場景重新鎖定滑鼠。加入 pointerlockchange 處理，以涵蓋瀏覽器攔截 Esc 先釋放游標的情況，並區別程式主動釋放。設定開啟時清除按住的鍵，阻擋遊戲鍵盤處理，保留原本已暫停的視窗狀態。此流程仍需真實瀏覽器驗證。

### 沒有加入的假選項

沒有新增解析度選擇、四段畫質、開場動畫、帳號同步、音效分類或 Godot 專用玩法。全螢幕使用瀏覽器實際狀態與使用者手勢，不宣稱重新整理能自動恢復瀏覽器全螢幕。TV iframe 的影音控制仍由其自身播放器處理。
