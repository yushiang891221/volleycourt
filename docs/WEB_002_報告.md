## 協定與資料

WebSocket：`/lobby?id=<分頁身分>&token=<私人重連憑證>`。身分與憑證為隨機 UUID，存於 sessionStorage 供換頁和重連使用；不出現在公開快照。這不是 WEB-004 的帳號登入。

所有 JSON 以 `k` 指定訊息種類：

| 方向 | 訊息 | 欄位與用途 |
| --- | --- | --- |
| 用戶→大廳 | hello | `name,status,code?`；設定暱稱與狀態，遊戲頁可持邀請代碼證明進房資格。 |
| 用戶→大廳 | status | `status,no?,code?`；狀態為大廳中、房間中、比賽中、練習中。 |
| 用戶→大廳 | create | `name,mode,password?`；mode 為 2v2 或 6v6。 |
| 用戶→大廳 | join | `no,password?`；檢查密碼、可見性與人數上限。比賽中仍允許加入。 |
| 用戶→大廳 | quick | `mode?`；挑等待中、無密碼、有空位且人數最多的房，平手依房號。 |
| 用戶→大廳 | chat | `text`；1～200 個 Unicode 字元，每位玩家每秒最多一則，同身分重連仍保留限制。 |
| 用戶→大廳 | room-update | `no,count,status,latency`；status 為 waiting／playing，latency 為毫秒或 null。 |
| 用戶→大廳 | room-close | `no`；只接受房主，關閉其成員資格並進入交接保留期。 |
| 用戶→大廳 | refresh | 重送完整快照。 |
| 大廳→用戶 | state | `players,rooms,chats`；初次連線及手動重新整理。 |
| 大廳→用戶 | players／rooms | `players` 或 `rooms`；資料有變化時廣播清單。 |
| 大廳→用戶 | chat | `chat:{id,name,text,at}`。 |
| 大廳→用戶 | joined | `no,code,mode,host`；只回給通過檢查的申請者。 |
| 大廳→用戶 | error | `reason`，繁體中文錯誤訊息。 |

公開玩家只有 `id,name,status,no`。公開房間只有 `no,name,mode,locked,count,max,status,hostName,latency,lastBeat`；每房上限 20。房號從 NO.101 起持久遞增，沒有設定虛構的全站房數上限，畫面以「—」表示。

房間代碼為 16 bytes 安全亂數轉成 32 碼十六進位字串。密碼僅儲存房間專屬隨機鹽及 SHA-256 雜湊，不儲存明碼；公開房間清單與廣播不含代碼、鹽、雜湊或重連憑證。密碼必須由輸入者傳到伺服器驗證，通過者也必須收到代碼，因此「網路封包看不到」指**無權限旁觀者的公開封包**，不包括當事人的 join／joined 私人交換；正式服務必須使用 WSS。

聊天保留最近 50 則，伺服器去除控制字元與雙向文字控制符；前端的聊天、暱稱、房名與伺服器欄位都用 textContent。一般訊息另有每連線每秒 12 則、訊息長度上限與開房間隔限制。錯誤會顯示在提示及開啟的原生 dialog 內。

## 房主交接規則

1. create／成功 join／持有邀請代碼的 status，會在伺服器建立成員資格。資格以玩家 ID 加私人重連憑證配對，僅知道公開 ID 不能冒充仍在線的房主。
2. 正常時只有房主可送 room-update。遊戲頁依現有 room-settings 的 isHost 判斷是否送出；不使用比賽模擬主機作為房主依據。
3. 房主大廳 socket 關閉或送 room-close 後，房間立刻從公開清單隱藏，但保留私有房間資料至最後心跳起算 30 秒，供換頁、重連與交接。
4. 原房主不再以同一身分在線於該房間時，已通過資格檢查的同房成員可送 room-update 接手；第一個符合資格的更新成為新房主，恢復公開清單、延續原房號／代碼／模式／密碼。
5. 若沒有接任者，alarm 在最後心跳滿 30 秒時清除紀錄；即使舊 socket 沒有正確斷開，也不會永久留下房間。新連線／訊息也會檢查過期資料。
6. join 的成員席位暫留 30 秒以涵蓋大廳→遊戲換頁；房主心跳更新實際人數。關頁送出通知是盡力而為，不能依賴瀏覽器一定成功送達。

限制：伺服器驗證成員資格及舊房主離線，但不獨立驗證 Ably 內的房主選舉結果、比賽狀態或人數；仍是工作單允許的簡單休閒房規則，並非帳號驗證或防作弊系統。持有房主分享的邀請連結即可直接進房，符合工作單要求。
