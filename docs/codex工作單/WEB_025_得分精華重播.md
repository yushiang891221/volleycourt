第一版的做法：
- `recFrame(t, idOf)`：從原本手動錄影的 `recTick` 抽出來，記一格畫面（球＋所有人）。手動錄影和精華共用。
- `HL` 物件：比賽中（`VM.on`）每 33 ms 記一格，只留最近 6 秒（`hlTick`，在 `14-loop.js` 呼叫）。全部在本機做，**不多傳任何網路訊息**。
- 誰得分：`vmPerfTouch` 記 `VM.hlLast`（最後碰球的人）。在 `vmPoint` 裡，如果最後碰球的人屬於得分隊，`by` 就是他；否則 `by=null`，代表對手失誤送分，**不重播**。這個規則要保留。
- `by`、`k`（動作：扣球、吊球、發球、攔網、攻擊）跟著原本的得分訊息 `pt` 一起送（`vmBroadcast(true, null, { win, why, by, k })`）。這只是在原本那則訊息裡多兩個欄位，沒有多送訊息。加入者在 `vmOnNet` 收到 `d.pt` 時呼叫 `hlOnPoint`。舊版伺服器的 `pt` 不會帶 `by`：這種情況只重播「落地得分」，鏡頭跟著球。
- `hlOpen(clips, rec)`：沿用原本回放的 `updateReplay` 畫人和球，`RP.view='hl'` 時用 `hlCamera()`。`rec=true` 時用 MediaRecorder 錄成 WebM。
- 跳過：任意鍵或點一下就跳過（開頭 0.3 秒內不算）。做影片時只有 Esc 能取消。
- 賽後下載：自己得的分存在 `HL.mine`。`VM.on` 從 true 變成 false 時，右下角出現「🎬 下載我的得分精華（N 球）」，按下去把每一球接起來，邊播邊錄，播完就下載。
- `hlOnPoint`、`hlReset` 已經加進 `build-headless.cjs` 的 STUB，伺服器不會跑到它們。

已經在瀏覽器實測：本機練習房（`gym.html?site=bs-shenjing&practice&dev`）裡，AI 發球得分會重播；我方失誤送分不會重播。**賽後下載還沒實測。**

## 使用者看過第一版後的要求（2026-11-17）
1. **失誤送分不用重播**（第一版已經這樣做，保留）。
2. **要有轉場畫面**：用 Play One 和那顆球（品牌球圖 `assets/img/brand/ball-512.webp`）做轉場。球從畫面**右上角斜著拉到左下角**，後面拖著一條 **Play One 文字標題帶**。標題帶就是分界線：**左邊是原本的比賽畫面，右邊是精彩重播的畫面**，重播畫面就這樣被帶進來。
3. **重播前後都要再長一點**：第一版大約只有 2.5 秒，使用者覺得「還沒進入狀況就播完了」。

## 要做的事
### A. 片段長度與比賽節奏
1. 片段範圍改成：從「得分那一下」（扣球、吊球、發球、攔網）**前 2.5 秒**開始，播到**落地後 1.2 秒**。擊球前後放慢的部分保留：擊球前 0.12 秒到擊球後 0.33 秒用 0.5 倍速，可以微調。環狀暫存改成最近 10 秒。
2. 現在下一球是得分後 3.2 秒發（`VM.next = { at: VM.t + 3.2 }`）。**有重播的球（`by` 不是 null）要把這段等待拉長**，長度約等於「得分後等 1 秒 → 轉場進 → 重播 → 轉場出」。請算出固定值寫成常數（例如 `HL_GAP`）。
   - 這段在 `vmPoint` 裡，伺服器會用 `build-headless` 產生同一份程式，所以本機房主和伺服器裁判的節奏會一樣。報告要寫清楚：**伺服器要重新部署才會生效**（部署會讓大家斷線，請不要自己部署）。
   - 有人跳過重播時，只是自己先回到現場畫面，不會讓下一球提早發。
   - 沒有重播的球（失誤送分）照原本 3.2 秒。
3. 得分後先停在現場畫面約 1 秒（看到球落地、比分跳動、記錄落地後的畫面），再進轉場。

### B. 轉場（進、出都要）
1. **轉場進**：約 0.5～0.6 秒。品牌球從右上角斜著飛到左下角，邊飛邊轉，後面拖著一條斜的 Play One 標題帶，配色照 Play One 現行風格（深綠＋香檳金，參考 `volleygame/play_one.html`）。標題帶往右上那一側已經是重播畫面，往左下那一側還是原本的比賽畫面。球飛出左下角後，整個畫面都是重播。
2. **轉場出**：重播結束或被跳過時，用同樣的動畫換回現場畫面（球一樣從右上飛到左下；標題帶右邊變成現場畫面）。如果使用者看了覺得要換方向再改。
3. 做法建議（可以換更好的）：轉場開始時把當下畫面凍結成一張圖，疊在 3D 畫面上面，用 CSS `clip-path` 斜線多邊形做斜切；下面的 3D 畫面直接開始畫重播。球和標題帶用 DOM 元素做。不要每格畫兩次 3D 場景。
4. **下載的影片也要有轉場**：每一球之間用同一個轉場。DOM 錄不進 MediaRecorder，所以下載時要另外用一張 2D 合成畫布，把 3D 畫面、凍結畫面、球、標題帶畫在一起，錄這張畫布。

### C. 第一版實測看到的問題（要修）
1. 左上角是沿用舊回放的資訊框（`RP.hud`，寫「擊球 0　最快 0 km/h」）：蓋到計分板，數字還是 0。精華模式不要用這個框，改成一個乾淨的 Play One 風格標籤，放在不會擋到計分板的位置，例如左下或下方中間：「REPLAY」＋得分者名字＋動作（例如「小明 扣球得分」）。畫面上方中間的「▶ 精彩重播・…／按任意鍵跳過」提示框跟它重複，請合併成一個；「按任意鍵跳過」可以用小字放在角落。
2. 球速標籤（`km/h`）偵測到的是 0 或錯的：查原因；修不好就在精華模式拿掉。
3. **鏡頭**：AI 在對面發球得分時，鏡頭卻在我方這邊、靠近我的人，沒有在發球者後方。請查 `hlCamera()`：得分者的人形是不是找對了（`by` 對應到畫面裡的編號，自己是 `'me'`），以及鏡頭位置被球館外框夾住時有沒有跑掉。理想效果：擊球前在得分者後方斜上方，看得到他和球；擊球後轉向跟著球，落地時看得到落點。發球、扣球、攔網各自試過。
4. 名字顯示：「AI發球得分」改成跟計分板一致的顯示名，中間要有適當的間隔。
