# 工作單 001：遊戲連線骨架（大廳、房間、同步）

> 背景：把排球遊戲做成獨立軟體。這張只做「連線骨架」，先證明大廳、多房間、順暢同步可行。
> 沒有排球、沒有球館場景，人物用膠囊體，地板用一塊平面。

## 專案位置與工具
- 新專案放 `D:\開排球場\volley-game\`，自己一個 git repo（只做本機提交，不要建遠端、不要推送）。
- Godot 4 穩定版，語言 GDScript。Godot 執行檔放在 `D:\開排球場\tools\godot\`，路徑不要寫死在程式裡。
- 不要動 `D:\開排球場\volleycourt\`、其他資料夾和 `tickets.md`。
- 不要加入任何付費服務、帳號或需要金鑰的東西。不要加 Steam。
- 除了 Godot 本體，不要下載其他東西；需要時停下來回報。

## 架構
同一份專案，用啟動參數分成兩種：
- `--server`：沒有畫面的權威伺服器，一個程式同時跑多個房間。
- 一般啟動：玩家端。

連線用 Godot 的 ENet（UDP）。伺服器說了算，玩家端只送輸入。

### 必須遵守
1. 用單一 ENet 連線（一個連接埠），不要每個房間開一個程式或連接埠。
2. 每個房間是獨立物件：自己的玩家名單、狀態和廣播對象。**A 房的封包絕對不能送到 B 房的人。**
3. 伺服器模擬固定 60 Hz，每秒送 30 次狀態。
4. 共用的移動計算放同一份程式，伺服器和玩家端都用它，不要各寫一份。
5. 訊息格式集中定義在一個檔案，用二進位封包，不要用 JSON。

## 功能
### 大廳
- 連線後自動收到房間清單：房名、人數／上限、是否遊戲中；有變動時自動更新。
- 建立房間（輸入房名，上限 12 人）、加入、離開。
- 房間滿了或不存在時回傳明確錯誤。
- 房主離開時，房主交給房內下一個人；最後一人離開時房間刪除。
- 斷線等同離開。

### 房間
- 第一人稱不用做，用固定的俯視鏡頭。
- WASD 移動，空白鍵跳。
- 看得到房內所有人移動，看不到別的房間的人。

### 順暢度（這張的重點）
- **自己的角色**：本機預測，按下去馬上動；收到伺服器結果時，重播還沒被確認的輸入來校正，不能有明顯拉回。
- **別人的角色**：內插顯示（約落後 100 ms），在兩筆狀態之間平滑接起來。
- 連線資訊顯示在畫面角落：延遲、每秒收發的位元組數。

## 完成標準（全部要有證據）
寫成可重複執行的腳本 `tests/run_all.ps1`，不需要人操作，回傳 0 才算通過：
1. 啟動無頭伺服器和多個無頭測試玩家，走完：看清單 → 建房 → 加入 → 離開 → 房主交接 → 房間刪除。
2. 房間隔離：同時兩個房間各 2 人移動，驗證完全收不到對方房間的玩家資料。
3. 滿房：第 13 人加入被拒絕。
4. 斷線：強制結束一個玩家程式，伺服器在 5 秒內把他移出房間。
5. 移動校正：用模擬的 100 ms 延遲和 2% 掉包，移動 20 秒，記錄預測和伺服器的最大誤差，要小於 0.5 m。
6. 負載：8 個房間、每房 12 個測試玩家，跑 60 秒，伺服器每一格都在 16 ms 內算完（記錄平均和最差值），並記錄每位玩家的平均流量。
