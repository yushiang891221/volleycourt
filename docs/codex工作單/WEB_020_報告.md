## 碰網與落地同步

`updateBalls` 原本每台電腦各自積分球的位置，網面與網帶碰撞也直接改寫本機球速。網路誤差修正稍有偏差，就可能讓接收端先碰網。現在 `b.room && !NET.ownBall` 的球略過網面與網帶反彈，收到同球權 `n` 事件時沿用既有直接對齊流程。

本機 `vbBlockTest` 與主機 `vmBlockTest` 仍在球網迴圈之外執行。新增測試讓遠端低球通過網面，再碰到本機玩家雙手，確認正式攔網流程發布 `block` 並取得球權。

第一次碰地時記錄 `floorHit` 與 `floorT`，在該物理小步立刻呼叫 `netFloorHit`。只有負責端發布一則既有 `ball` 類型訊息，額外攜帶 `g = [x, z]`。每段擊球球權只回報第一次落地，後續彈地不重送。新擊球會重設落地狀態。

接收端核對球權序號、球權持有人及訊息來源，確認落點為兩個有限數值後直接對齊地板落點，清除誤差與接觸動畫。重複落地事件及落地後同球權的一般校正不覆蓋已確認的落點。新擊球仍可開始下一段球路。

### 主機原有判分方式與本次變更

`vmJudge` 使用 `VM.ball.floorHit`，透過 `vmL` 換成球場座標。界內判斷為長向絕對值不超過 `9 + BALL_R`，寬向不超過 `4.5 + BALL_R`。界內由落點所在隊伍失分，界外由最後觸球隊伍失分，最後觸球隊伍未知時沿用落點側判斷。接著呼叫 `vmMark`、`vmPoint`，界外另呼叫 `vmOut`。

本次沿用上述界內外、隊伍與得失分計算，改變落點資料來源及等待條件。

- 主機是負責端時使用本機落點，保留原有附近真人可能已救球的 600 ms 等待。
- 主機接收遠端球時，收到有效落地事件就以回報落點判分。
- 若本機已模擬落地，經過 500 ms 仍沒有回報，就使用保留的本機落點判分。時間採真實毫秒，與球速倍率分開。
- 等待期間若收到新擊球，舊的落地狀態清除。

## 第三下自動回送

本機的接球、蹲接、撲救、舉球與 E 推球入口，在比賽 rally 且 `vmThird()` 成立時，於接觸點修正完成後計算自動回送速度。方向由玩家隊伍所在半場決定，使用反推過網高度的拋物線，目標設在對面深處。

正常品質的縱向落點限制在 4～8.6 m，橫向限制在 ±4.1 m。品質低於 0.32 時仍朝對面並保留過網高度，橫向誤差允許擴大到 ±6 m，因此可能出界。提示為「第三下：自動送回對面」。

攻擊入口的扣球、吊球、跳躍攻擊與原有下手攻擊保留原瞄準流程。第一、二下及非比賽教學／練習維持原有球路。新增測試逐一比對第一、二下正式接球結果與 WEB-019 基準相同。

AI 的第三下已走原有攻擊流程，舉得太低或碰不到攻擊點時走 `vmAiFree`，以 `vmPickGap` 選對面深處落點。`vmAiTouch`、`vmAiFree`、`vmAiRole` 與真人／AI 攔網函式皆通過 WEB-019 逐字比對。
