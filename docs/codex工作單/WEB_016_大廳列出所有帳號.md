# 工作單 WEB-016：大廳玩家清單列出所有註冊帳號（在線優先、離線顯示多久前）

建立：2026-11-12。在 `volleycourt` 的 `game-site` 分支做（目前 main＝game-site＝1c84d56）。只做電腦版。
Codex 用量不可超過 50%；做完就停。

## 使用者的需求（暫時性的做法）
大廳右邊的玩家清單，現在只列出連著大廳的人。改成：
- **只要有註冊帳號（profiles 有暱稱）就列出來**。
- 在線的照現在一樣顯示狀態（大廳中／房間中／比賽中／練習中），**排在前面**。
- 不在線的顯示「離線」＋多久前上線，例如「離線・剛剛」「離線・12 分鐘前」「離線・3 小時前」「離線・2 天前」；從來沒有紀錄的只寫「離線」。不在線的照最近上線時間排（越近越前面）。
- 自己仍然排第一。

## 現況（規劃端已查）
- 在線名單：Cloudflare 大廳伺服器 `rt-worker/src/lobby.js` 的 `players()`，用 WebSocket 送 `{id,name,status,no}`；`lobby.js` 的 `renderPlayers()`（約 46 行）畫出來，每頁 8 人。`name` 就是帳號暱稱（`profiles.nickname` 是 unique）。
- 帳號：Supabase `profiles`（001），已登入的人可以讀 `id, nickname, appearance`。現在**沒有任何「最後上線時間」**：`active_sessions.updated_at` 只在登入那一下更新，不能拿來用。

## 要做的事
1. **SQL：新增 `server/supabase/013_last_seen.sql`**（可重複執行，接在 012 後面）
   - `profiles` 加欄位 `last_seen_at timestamptz`（可以是 null）。不要開放一般使用者直接寫這個欄位。
   - 函式 `touch_seen()`（security definer，只給 authenticated）：把自己的 `last_seen_at` 設成 now()；如果距離上次不到 60 秒就不寫（省資料庫寫入）。
   - 函式 `lobby_accounts()`（security definer，只給 authenticated）：回傳所有暱稱不是 null 的帳號 `nickname, last_seen_at`，依 `last_seen_at desc nulls last`，最多 500 筆。不要回傳 id、email 或其他欄位。
2. **前端記錄上線時間**：登入後在大廳或球館（gym.html）頁面開著時，呼叫 `touch_seen()`：進頁面一次，之後每 5 分鐘一次（分頁在背景也照樣 5 分鐘一次即可，不要更密）。用 `auth.js` 現有的 rpc 包裝。函式還沒建立（使用者還沒執行 013）時要安靜失敗，不能影響遊戲或大廳。
3. **大廳清單**（`lobby.js`）：
   - 進大廳時呼叫 `lobby_accounts()`，之後每 2 分鐘重新拿一次。
   - 合併：在線名單（大廳伺服器）用暱稱對上帳號；在線的用即時狀態；帳號清單裡不在線的標成離線＋多久前。在線但不在帳號清單裡的人也要照常顯示。
   - 排序：自己 → 在線（照現在的名字排序）→ 離線（最近上線的在前）。
   - 「多久前」照當下時間算，畫面每分鐘更新一次文字即可：未滿 5 分鐘「剛剛」、未滿 1 小時「N 分鐘前」、未滿 1 天「N 小時前」、其他「N 天前」。
   - 離線的列外觀變淡（灰色狀態標籤），但右鍵玩家選單、查看個人檔案、加好友都要照常能用。
   - 人數文字改成像「在線 3 人・共 25 人」。分頁每頁 8 人維持不變。
   - `lobby_accounts()` 失敗（例如還沒執行 013）時，退回只顯示在線名單，跟現在一模一樣，不跳錯誤訊息。
4. 好友面板裡「在大廳的好友亮綠點」的判斷要繼續只算真的在線的人，不能把離線帳號當成在線（目前 `openFriendsPanel(() => players.map(p => p.name))` 傳的是在線名單，合併後要確認傳的仍是在線的）。

## 不要做
- 不改大廳伺服器（`rt-worker/`）、不改房間、比賽、連線、成就。不做手機版。不改 `blender/`、`models/`。不推送、不部署、不要自己去 Supabase 執行 SQL。一行程式中間的註解用 `/* */`。
