# 工作單 WEB-017：房間裡按 Enter 打字聊天

建立：2026-11-12。在 `volleycourt` 的 `game-site` 分支做（目前 main＝game-site＝c394a10）。只做電腦版。
Codex 用量不可超過 50%；做完就停。

## 使用者的需求
在房間（球館，gym.html 連線中）裡可以打字聊天：**按 Enter 跳出輸入框**，打完再按 Enter 送出。

## 規格
1. **開關輸入框**
   - 在房間裡（`NET.on`）按 Enter：畫面下方偏左跳出輸入框並自動聚焦。
   - 輸入框裡按 Enter：有字就送出並關閉；沒字就直接關閉。按 Esc：不送、關閉。
   - 打字期間，所有遊戲按鍵（移動、跳、攔網、表情、視角等所有 keydown 處理，包含 `settings.js` 的自訂按鍵）都不能被觸發；角色停下來，不要繼續往前走（放開按住的移動鍵狀態）。關閉後恢復正常。
   - 練習模式（沒有連線）不用開聊天。
2. **Enter 衝突**：`settings.js` 目前 `['start','房主開始遊戲','Enter']`。改成 Enter 給聊天，「房主開始遊戲」的預設鍵換成一個目前沒被使用的鍵（建議 `KeyG`，先檢查沒衝突），按鍵設定畫面要顯示新的鍵。使用者如果自己改過按鍵設定、存的是 Enter，也要改成新的預設鍵，避免跟聊天搶。畫面上的開始按鈕照舊。新增一行「聊天」說明在按鍵說明裡（固定 Enter，不用可自訂）。
3. **送出與顯示**
   - 走現有房間連線 `NET.tx.publish('chat', { id, n, t })`（不要另開頻道、不要改 `rt-worker/`）。
   - 每則最多 60 字，去掉前後空白與控制字元；每人每秒最多 1 則（送的人那邊擋）。收到的訊息也要截斷到 60 字。
   - 顯示：畫面左下（不要擋住計分板、輪轉表、按鍵提示等現有介面，自己確認位置）一個半透明聊天紀錄，保留最近 6 則，「名字：內容」，自己的訊息用不同顏色。新訊息出現約 8 秒後淡出；輸入框打開時全部顯示。
   - 同時在說話的人頭上冒對話泡泡約 4 秒（參考現有 `emoBubble`，約 7607 行；AI 不會說話）。
   - 文字一律用 textContent 放進畫面，不能用 innerHTML（防止插入程式碼）。
   - 場上的人、觀眾、比賽中、等待中都可以聊。
4. **額度**：聊天只在有人送出時才傳，不要加任何定時傳送。

## 不要做
- 不改大廳聊天、`rt-worker/`、比賽、AI、連線節奏、成就。不做手機版。不改 `blender/`、`models/`。不推送、不部署。一行程式中間的註解用 `/* */`。
