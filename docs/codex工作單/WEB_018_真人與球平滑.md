# 工作單 WEB-018：看真人隊友不再微微瞬移、看球不再閃一下（訊息總量不增加）

建立：2026-11-13。在 `volleycourt` 的 `game-site` 分支做（目前 main＝game-site＝10d8768）。只做電腦版。
Codex 用量不可超過 50%；做完就停。先讀 `codex工作單/WEB_015_報告.md`（AI 的時間軸內插就是這張要照著做的範本）。

## 使用者實測（3 人連線）
各自看自己的畫面很順；但**看別的真人會有微微的瞬移**，**看球會有微微的閃現**。

## 原因（規劃端已查）
1. **真人**：`netTick()`（gym.html 約 7740 行之後的 `for (const p2 of NET.peers.values())`）用最後一筆位置＋速度往前外推，最多 0.5 秒＋延遲。對方一轉向或急停就衝過頭再被拉回。`netOnMessage` 的 `'st'`（約 7677 行）其實已經有在存 `p2.buf`，但沒有拿來播放。WEB-015 只把 AI 改成時間軸內插，真人沒改。
2. **球**：別人擊球的訊息晚 0.05～0.15 秒才到，這段時間本機的球沿舊路線繼續飛，收到後 `b.err` 在 `updateBalls()`（約 6793 行）用 `dt * 10`（約 0.1 秒）快速拉回新路線，看起來像閃一下；拉的途中如果會低低穿網，會直接跳過去（約 6796 行）。

## 要做的事
1. **真人改成時間軸內插**（做法照 WEB-015 的 `vmAiSnapshot`／`vmAiPlayback`，最好共用同一套函式）
   - 每則 `st` 加一個送出時間欄位（例如 `ts`＝送出端 `performance.now()/1000` 取兩位小數）。**只加欄位，不增加訊息數**。收方用它排時間軸（每個 peer 自己算時間差），沒有 `ts`（舊版）就退回用收到時間。
   - 播放延遲＝1.5 倍平均收到間隔，限制 120～300 ms，平滑變化；兩筆之間內插位置與朝向（朝向要走最短角度）；資料用完最多外推 0.2 秒後停住，新資料到了平滑靠回；差超過 3 m 直接定位（剛進房、傳送）。
   - **起跳**：真人現有的 `p2.jump`（照延遲補算的弧線）保留在「現在時間」播放；收到新的起跳事件時，人也靠到那一筆 `st` 的 x、z（起跳點），落地前不用延遲的緩衝位置——跟 WEB-015 AI 的處理一樣，避免助跑途中先跳。
   - **動作**（pose、攔網手的位置、拿著的球）用最新一筆，不要延遲，才跟球對得上。
   - 走路擺腿用實際畫出的速度。
2. **球的修正改柔和**
   - 一般校正和別人新擊球時的拉回，改成約 0.25 秒內平順靠過去（不是 0.1 秒）；誤差越小越快消失沒關係，但不能有一格內明顯跳動。
   - **例外要快**：球離本機玩家 3 m 內、或預計 0.4 秒內會到本機玩家附近時，用原本的速度修正（本機要接球，位置不能不準）。
   - 穿網保護保留，但改成：只有「拉的途中這一格真的會從網的下方穿過」才直接對齊，其他情況不要跳。
   - 碰網（`d.n && sameOwner`）照舊直接對齊。
   - 不改球的物理、擊球判定、誰負責球的規則。
3. 不改 AI 的部分（WEB-015 已做好），不改送出節奏。
