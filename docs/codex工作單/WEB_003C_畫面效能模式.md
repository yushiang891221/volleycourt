# 工作單 WEB-003C：畫面效能模式（流暢優先／平衡／畫質優先）、FPS 上限、顯示 FPS

建立：2026-11-04。**排在 WEB-003（A、B 段）之後**，在 `volleycourt` 的 `game-site` 分支做；開工前先確認 WEB-003 已提交、工作目錄乾淨。
先讀：`codex工作單/WEB_001C_報告.md`（個人設定面板 `settings.js`）。Godot 版參考（只讀）：`volley-game/src/prefs.gd` 的 `QUALITY`（低／中／高／極高）。
只做電腦版。**不改玩法、物理、擊球、手感。**

## 現況（gym.html 約 1296～1345 行）
- 畫質只有 `high`／`low`（設定面板「畫面」分頁的「畫質」），`applyQuality()` 切 GTAO、像素比、陰影貼圖大小。
- `watchPerf()`：高畫質時太卡會自動降成省電；`syncGameFast()`：比賽中自動關 GTAO、像素比 1。
- 畫面更新率沒有上限，跟著螢幕的 requestAnimationFrame。

## 要做的事
### 1. 「畫質」改成「效能模式」三段（設定面板「畫面」分頁）
| 模式 | 內容（可依實測微調，寫進報告） |
|---|---|
| **流暢優先** | 關 GTAO、關泛光（bloom）、像素比 1、陰影 1024、比賽中也一樣 |
| **平衡**（預設） | 現在的行為：走動時開 GTAO、像素比最多 1.5、陰影 2048；比賽中自動減輕（`syncGameFast`）；太卡自動降一級（`watchPerf`） |
| **畫質優先** | 全開：GTAO、泛光、像素比 `min(devicePixelRatio, 2)`、陰影 4096；比賽中也不減輕；不自動降級 |
- 舊設定轉換：`high` → 平衡、`low` → 流暢優先（`settings.js` 的舊設定遷移那段一起改）。
- 每個選項底下一行小字說明差別。
- 自動降級後要提示一次（toast），並在設定面板顯示「目前因為太卡暫時降低畫質」。

### 2. FPS 上限
- 設定面板「畫面」分頁加下拉：**不限（跟螢幕）**、144、120、60、30。預設「不限」。
- 做法：在主迴圈依上限跳過渲染（requestAnimationFrame 照跑，但距上次畫面不到 1/上限 秒就不 render）。**遊戲邏輯和物理的時間步進不能因此改變**：先確認現在的物理是不是用每格的 dt 算；如果跳格會讓物理或連線送訊息頻率變，就只跳過「畫」、不跳過「算」，寫進報告。
- 分頁在背景時照瀏覽器原本的行為，不額外處理。

### 3. 顯示 FPS
- 設定面板「畫面」分頁加勾選「顯示 FPS」（預設關）。開了在畫面右上角（房間資訊／按鈕不要擋到）小字顯示 FPS，每 0.5 秒更新一次，例如「FPS 60」。
- 大廳不用顯示。

### 4. 設定存放
沿用 `vb.settings`，新欄位：`perf`（`smooth`｜`balanced`｜`quality`）、`fpsCap`（0＝不限、144、120、60、30）、`showFps`（布林）。改了馬上生效、不用重新整理。

## 不要做
- 不改物理、擊球、AI、連線協定和送訊息頻率。
- 不推送、不部署，不動 `main`、`planning-site`。

## 驗收
1. 三種模式切換馬上生效：用 `renderer.getPixelRatio()`、`gtao.enabled`、`bloom.enabled`、陰影貼圖大小確認。
2. FPS 上限設 30／60 時，顯示的 FPS 接近上限；球的飛行時間、移動速度跟「不限」時一樣（寫一個自動檢查：同一段模擬在不同上限下結果一致）。
3. 舊的 `high`／`low` 設定會正確轉成平衡／流暢優先。
4. 舊的自動檢查都還要過；新寫 `tools/verify-web003c.cjs`。
