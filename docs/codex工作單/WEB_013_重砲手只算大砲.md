# 工作單 WEB-013：重砲手成就只算大砲（OH）位置的重扣

建立：2026-11-12。在 `volleycourt` 的 `game-site` 分支做（目前最新提交 33ba9da）。只做電腦版。
Codex 用量不可超過 50%；這張很小，做完就停。

## 使用者的規則
- 「重砲手」成就（cannon1～cannon5，100／500／1000／3000／5000）只算**在大砲（OH）位置**扣球得分。
- 快攻有自己的成就（影子排球員），**快攻得分不算重砲手**。
- 吊球（tip）、一般擊球（hit）也不算，只算扣球（spike）。

## 現況
- `gym.html` 約 9982 行：得分時 `L.kind` 是 spike／tip／hit 都記進 `k`（扣球得分）；`L.quick` 記進 `qk`。
- 約 10030 行：`perf` 送給 Supabase 的 `record_match`。
- `server/supabase/009_match_rating.sql`：`record_match` 用累計的 `r.kills` 判斷 cannon1～5。
- 位置：`VM.role[球員 id]`（只有 6 人制有位置；`vbMyRole()` 在非 6 人制回傳 null）。

## 要做的事
1. **遊戲端**：`mrecPf` 加一個欄位 `kc`（重砲得分）。得分時若 `L.kind === 'spike'`、不是快攻（`!L.quick`）、不是第二下自己扣（`!L.self`）、而且這名攻擊手**擊球當下**的位置是 OH（6 人制 `VM.role[L.id] === 'OH'`），`kc++`。位置要在擊球那一刻記進 `MREC.last`（例如 `L.role`），不要在得分時才查（輪轉可能已經變了）。非 6 人制沒有位置，不算。`perf` 加送 `kc`。原本的 `k`（扣球得分）照舊，評分、經驗都不要變。
2. **伺服器**：新增 `server/supabase/011_cannon_oh.sql`（可重複執行，先要 009）：
   - `player_progress` 加欄位 `cannon_kills integer not null default 0`（`add column if not exists`）。
   - `create or replace` `record_match`：從 009 整份複製，只改兩處：讀 `p_perf->>'kc'`（限制範圍照其他欄位的寫法，例如每場上限跟 `k` 一樣）累加到 `cannon_kills`；cannon1～5 改用 `r.cannon_kills` 判斷。其他全部一字不改。
   - 已經拿到的重砲手成就**保留不收回**；新計數從 0 開始（舊的扣球得分分不出位置，不轉移）。
3. **顯示**：`progress.js` cannon1～5 說明改成「在大砲（OH）位置扣球得分累計 N 分（快攻、吊球不算）」，系列說明也跟著改。成就面板進度條若有讀 `kills` 顯示重砲手進度，改讀 `cannon_kills`（`my_progress` 回傳整列，新欄位會自動帶到）。

## 不要做
- 不改其他成就、評分、經驗、金幣、玩法。不做手機版。不改 `blender/`、`models/`。不推送、不部署、不要自己去 Supabase 執行 SQL。一行程式中間的註解用 `/* */`。
