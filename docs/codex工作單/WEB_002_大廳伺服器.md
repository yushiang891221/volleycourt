# 工作單 WEB-002：大廳伺服器（房間清單、在線玩家、大廳聊天、快速加入、密碼房）

建立：2026-11-04。在 `volleycourt` 的 `game-site` 分支做（目前跟 main 一樣在 `32b65b3`）。
先讀：`tickets.md` 的 Ticket 4（大廳主畫面樣式、工作單順序）、`codex工作單/WEB_001B_報告.md`、`codex工作單/WEB_001C_報告.md`、`rt-worker/src/index.js`。

## 目標
大廳現在的房間清單、在線玩家、留言板都只有自己看得到。這張要接上真的大廳伺服器，讓所有人看到同一份資料。
**房間裡的比賽連線不動**（維持 Ably 為主、Cloudflare 房間伺服器備援，手感不變）。大廳伺服器只管「大廳的資訊」。

## 架構
在現有的 Cloudflare Worker（`rt-worker/`）加一個 **Lobby Durable Object**，全站只有一個實例（`idFromName('main')`）：
- 新路徑 `/lobby?id=玩家ID`（WebSocket），沿用現有的 `ALLOWED_ORIGINS` 檢查和 localhost 例外。
- `wrangler.toml` 加綁定 `LOBBY` 和新的 migration（`tag = "v2"`、`new_sqlite_classes = ["Lobby"]`，免費方案只能用 SQLite 版）。**不能改 v1、不能動 Room 的行為。**
- 用 WebSocket Hibernation API（跟 Room 一樣 `ctx.acceptWebSocket`、`setWebSocketAutoResponse('ping','pong')`），省免費額度。
- 每個人的資料放在 `serializeAttachment`，大廳醒來時能還原；房間清單和聊天紀錄存在 DO storage（SQLite），重啟不會全部消失。

### 大廳要記的東西
- **在線玩家**：ID、暱稱、狀態（大廳中／房間中／比賽中／練習中）、在哪個房間（房號）。等級先不顯示（WEB-004 有帳號才有）。
- **房間**：房號（大廳自己發，從 NO.101 往上）、房名、模式（2v2／6v6…）、有沒有密碼、目前人數／上限 20、狀態（等待中／比賽中）、房主暱稱、房內平均延遲（房主回報）、最後心跳時間。
  - **房間代碼（真正進房用的 Ably／房間伺服器頻道名）不能出現在清單裡**，只有通過檢查的人才拿得到。代碼改成 10 碼以上的隨機字（不好猜）。
  - 密碼：大廳只存雜湊（例如 SHA-256 加房間專屬鹽），不存明碼。
- **聊天**：最近 50 則，每則最多 200 字、每人每秒最多 1 則；伺服器過濾控制字元。前端一律用 textContent 顯示。

### 訊息（JSON，自己定細節，寫進 `rt-worker/src/index.js` 開頭註解）
- 用戶 → 大廳：`hello {名字, 狀態}`、`status {狀態, 房號}`、`chat {文字}`、`create {房名, 模式, 密碼?}`、`join {房號, 密碼?}`、`quick {模式?}`、`room-update {房號, 人數, 狀態, 延遲}`（只有房主能送）、`room-close {房號}`。
- 大廳 → 用戶：`state {玩家清單, 房間清單, 最近聊天}`（剛連上）、玩家／房間的增減更新、`chat`、`joined {房號, 代碼, 模式, 是否房主}`、`error {原因}`（密碼錯、房間滿、房間不存在、太頻繁…，用中文說明）。
- 房主斷線或 30 秒沒有 `room-update` → 房間從清單移除（房主換人時，新房主接著送心跳就會延續，見下面）。

## 前端
### 大廳 `index.html` / `lobby.js`
- 連上大廳伺服器：網址從 `api/rt-config` 的 `cf` 推出來（把 `/room` 換成 `/lobby`；`cf` 是 `wss://網域`，就接 `/lobby`）。本機開發可以用 `?lobby=ws://localhost:8787` 指定（只有在 localhost 才接受這個參數）。
- 頂列狀態顯示連線中／已連線／連不上（連不上要自動重試，間隔慢慢拉長）。
- **房間清單**：用 WEB-001B 做好的卡片顯示真資料，分頁、模式篩選、重新整理都要能用。點卡片 → 有密碼就跳出密碼框 → 送 `join` → 拿到代碼後進 `gym.html?site=bs-shenjing&room=代碼&mode=模式`。房間滿了或比賽中的卡片要看得出來（比賽中可以進去當觀眾，先允許進房，WEB-003 再處理觀眾）。
- **開啟房間**：送 `create`，大廳回 `joined`（是房主）後進房，網址帶 `host=1`。
- **快速加入**：送 `quick`（帶目前篩選的模式），大廳挑「等待中、沒密碼、還有空位、人最多」的房間；沒有就提示「目前沒有可加入的房間，要不要自己開一間？」。
- **在線玩家**：真資料，自己置頂高亮，狀態用不同顏色，分頁。
- **大廳留言板**：送出經過伺服器廣播給所有人；進大廳時看得到最近的聊天；系統公告保留。
- 拿掉 WEB-001 的「用代碼加入」輸入框。`?demo=1` 的假資料可以保留給開發看樣式，但連上伺服器時不要混進真資料。
- 邀請連結：房間裡原本複製邀請連結的功能如果還在，連結格式維持 `gym.html?...&room=代碼`（拿到連結的人可以直接進，這是房主自己分享的）。

### 遊戲頁 `gym.html`
- 進房後也連一條大廳連線（輕量，只送狀態）：狀態依情況送「房間中」「比賽中」「練習中」。
- **房主**（用 WEB-001C 的 `room-settings` 判斷誰是房主）每 10 秒、以及人數或比賽狀態改變時送 `room-update`。房主換人時，新房主接手送心跳；大廳要接受「同房間、由房內成員送來、且原房主已離線」的接手（想個簡單可靠的規則，寫進報告）。
- 最後一個人離開／房主關頁時送 `room-close`（送不到也沒關係，30 秒心跳逾時會清掉）。
- 練習模式不建房間，只回報「練習中」。
- 大廳連線斷了**不能影響房間裡的比賽**，只要背景重連就好。

## 不要做
- 不改房間裡的比賽連線、物理、擊球、AI。
- 不改 Room 這個 Durable Object 的行為和 v1 migration。
- **不部署 Worker、不推送、不動 main**（部署 Worker 要使用者登入 Cloudflare，規劃端驗收後再處理）。
- 不放金鑰。只做電腦版。

## 驗收
1. 在 `rt-worker/` 跑 `npx wrangler dev --port 8787`（本機模擬 Durable Object，不用登入）；另外用 `python -m http.server 5180 -d volleycourt` 開網站，大廳網址加 `?lobby=ws://localhost:8787`。
2. 開兩個瀏覽器分頁（不同暱稱）：兩邊都看到對方在線；A 開房，B 的清單馬上出現；B 點進去，兩邊人數都變 2；A 關分頁後，房主換成 B、房間還在清單上；B 也離開後，房間在 30 秒內消失。
3. 密碼房：密碼錯進不去、對了才進得去；清單和網路封包裡看不到房間代碼和密碼。
4. 快速加入挑對房間；沒有房間時有提示。
5. 聊天兩邊都看得到；太長、太快會被擋；`<script>` 之類的文字照字面顯示。
6. 大廳伺服器關掉時：大廳顯示連不上並重試；已經在房間裡的比賽照常進行。
7. 能寫成自動測試的寫進 `tools/`（例如用 Node 直接連 wrangler dev 的 WebSocket 測上面 2～5）。
