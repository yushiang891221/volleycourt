# 工作單 WEB-012：好友邀請通知、右鍵玩家選單、個人檔案、拿掉羽球按鍵

建立：2026-11-12。在 `volleycourt` 的 `game-site` 分支做（目前最新提交 828daa2）。只做電腦版。
Codex 用量不可超過 50%；照順序做，做完就停。

## 使用者回報的問題
- 加好友後，對方完全不知道收到邀請（只有大廳「好友」按鈕的紅色數字，而且 60 秒才更新一次，要自己打開好友面板才看得到）。
- 大廳在線玩家清單上每個人都掛著「＋好友」按鈕，已經是好友或已經邀請過了也還是顯示「＋好友」。
- 使用者想要：在玩家名字上**按右鍵跳出小選單**，裡面有「檢視個人檔案」和「加好友」。
- 按鍵設定裡還有「羽球／匹克球：軟球／抽球／挑球」(J／K／L)，遊戲網站只打排球，用不到。

## 現況（給你參考）
- 後端 `server/supabase/005_friends.sql`：`friend_request(暱稱)`、`friend_respond(對方 id, 接受?)`、`friend_list()`（state＝friend／incoming／outgoing）。`007_friend_badge.sql`：`friend_badge()` 回傳未讀私訊＋收到邀請數。
- 前端 `friends.js`：`addFriend`、`refreshBadge`（60 秒查一次）、`openFriendsPanel`（收到的邀請在面板裡有接受／拒絕）。
- 「＋好友」按鈕在 `lobby.js:56`（大廳在線玩家）和 `gym.html` 約 7075 行（房間內 `#room-list` 的 `.mp-add`）。
- 玩家資料：`profiles`（nickname、appearance 外觀代碼，含裝備）、`player_progress`（exp、stats 勝敗、achievements 成就代碼陣列、title 稱號）、`teams`／`team_members`（球隊、球隊球衣）。等級規則是每 500 經驗升一級（照 `character-panel.js` 現有算法，不要自己另算）。
- `character-panel.js` 有 `preview(img, code)` 可以把外觀代碼畫成角色圖，成就資料和圖示也在那邊（`openAchievementPanel`）。

## 要做的事
1. **收到好友邀請要通知**
   - `refreshBadge()` 查到「收到的邀請」比上次多（或剛登入進大廳時有未處理的邀請），就抓一次 `friend_list()`，對每個新的邀請在畫面右下角跳一張通知卡：「〇〇〇 想加你好友」，按鈕「接受」「拒絕」「檢視檔案」。同一個邀請只跳一次（記在 `sessionStorage`，讀寫都要 try/catch）。只有收到的邀請數增加時才抓整份清單，平常照舊只拿一個數字（省流量）。
   - 接受／拒絕後卡片消失、紅色數字馬上更新。
   - 大廳、進房間後（遊戲畫面）都要能看到這張卡；比賽進行中不要擋畫面：比賽中先不跳，比賽結束回到房間再跳。
   - 如果大廳連線本來就有「傳訊息給特定玩家」的功能，送出邀請時順便通知對方立刻查一次；**沒有就不要為此改伺服器**，靠 60 秒查一次即可，寫進報告。
2. **右鍵玩家選單（取代「＋好友」按鈕）**
   - 拿掉 `lobby.js` 和 `gym.html` 房間清單裡的「＋好友」按鈕。
   - 在這些地方的玩家名字上按右鍵，在滑鼠位置跳出小選單（點選單外、按 Esc、捲動時關掉；不要超出視窗邊）：大廳在線玩家清單、房間內玩家清單、好友面板裡的好友／邀請列。自己的名字不出現選單。
   - 選單項目：
     - 「檢視個人檔案」
     - 好友那一項依關係顯示：還不是好友＝「加好友」；我已邀請＝「已送出邀請（取消）」；對方邀請我＝「接受好友邀請」；已是好友＝「傳私訊」（打開好友面板並選到這個人）。
   - 關係用一份快取的 `friend_list()` 判斷（打開選單時如果快取超過 60 秒才重抓），不要每次右鍵都打一次伺服器。
   - 沒登入（訪客）：選單仍有「檢視個人檔案」，好友項目顯示「登入後才能加好友」並且不能按。
   - 名字上加個小提示（滑鼠移上去 `title`：「按右鍵查看更多」），讓人知道可以按右鍵。
3. **個人檔案視窗**
   - 新增 `server/supabase/010_public_profile.sql`（可重複執行，格式照 005／007）：函式 `public_profile(p_nickname text) returns jsonb`，只給登入的人（`authenticated`）用，回傳：暱稱、外觀代碼、經驗（前端換算等級）、稱號、已解鎖成就代碼陣列、勝場／敗場總數（從 `stats` 加總）、球隊名稱與球隊球衣（沒有就 null）。**不要回傳** email、金幣、使用者 id 以外的帳號資料；找不到暱稱回傳 null。
   - 前端新視窗（對話框）：左邊用 `preview()` 畫出對方現在的角色（穿著外觀代碼裡的裝備；有球隊就照球隊球衣，照現有遊戲裡決定球衣的規則），右邊顯示暱稱、Lv、稱號、球隊、勝敗、成就（已解鎖數／總數，並列出已解鎖成就的圖示和名稱，可捲動）。視窗下方有和選單一樣的好友按鈕。樣式照現有成就／裝備面板。
   - 訪客、或還沒執行 010 的 SQL：顯示「要登入才能看個人檔案」／「個人檔案功能還沒開通」，不能壞掉（錯誤轉中文照 `auth.js` 現有寫法）。
4. **拿掉羽球／匹克球按鍵**
   - 按鍵設定面板不再顯示 `j`、`k`、`l` 三列（`settings.js` 第 11 行）。如果遊戲程式還會讀這三個鍵，就保留內部預設值、只是不顯示，避免壞掉；寫進報告你用哪一種做法。舊玩家存檔裡的這三個鍵不能讓設定讀取失敗。

## 不要做
- 不改玩法、物理、數值、比賽規則、連線同步、成就與經驗計算。不刪羽球／匹克球的遊戲程式本身（只拿掉按鍵設定那三列）。不做手機版、觸控。不改 `blender/`、`models/`。不推送、不部署、不要自己去 Supabase 執行 SQL（使用者會自己貼）。一行程式中間的註解用 `/* */`。
