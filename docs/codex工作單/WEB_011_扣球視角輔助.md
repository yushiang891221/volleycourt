# 工作單 WEB-011：扣球視角輔助（體力越少輔助越少）

建立：2026-11-12。在 `volleycourt` 的 `game-site` 分支做（目前最新提交 aa8733b）。只做電腦版。
這張很小，只改 `gym.html`（和驗收腳本）。Codex 用量不可超過 50%，做完就停。

## 要做的事
攻擊跳起來時，鏡頭自動稍微往下壓，讓攻擊手由上往下看對面場地，比較好瞄準扣球線路。體力越少，往下壓得越少。

1. **什麼時候作用**
   - 只在一般攻擊跳：`vbJump()` 起跳、而且不是攔網（`walk.air.block` 為 false）。
   - 跳發球（約 6667 行 `staPay('jserve')` 那個 `walk.air`）不要作用：在那個物件加旗標（例如 `serve: true`）排除。
   - 練習扣球動畫 `walk.spike`（約 6390～6439 行）本來就有自己的鏡頭動作，不要動。
   - 起跳時附近 4 m 內要有正在飛的球（不是靜止球）才輔助；原地亂跳不輔助。
   - 跟著設定裡現有的「視角輔助」開關（`VBSettings.values.cameraAssist`）：關掉就完全不輔助。不要新增設定項目。

2. **壓多少（體力決定）**
   - 在 `vbJump()` 裡算好輔助強度 `k`，存進 `walk.air`（例如 `walk.air.camK`）：
     - 沒有體力系統時（`staGame()` 為 false，例如練習房）：`k = 1`。
     - 體力夠：用現在的 `tired`（0.4～1）換算成 0～1，`k = (tired - 0.4) / 0.6`，體力滿＝1、快沒體力＝接近 0。若 `tired` 一直是 1 導致沒差別，改用起跳前的體力比例（`STA.v / 上限`），寫進報告。
     - 「體力不夠：只能小跳」那條路：`k = 0`，完全不輔助。
   - 最多往下壓 `CAM_SPIKE_MAX = 0.21` 弧度（約 12°），實際壓 `0.21 × k`。這個數字放成常數，方便之後調手感。

3. **怎麼壓（不能搶滑鼠）**
   - 用「疊加偏移量」做，不要直接把 `walk.pitch` 設成固定值：每幀算出這一刻的目標偏移 `off`，`walk.pitch += off - a.camOff; a.camOff = off;`。玩家在空中動滑鼠照樣有效。
   - 往下看是 `walk.pitch` 變小（負值方向）。
   - 偏移曲線：起跳後慢慢往下、到最高點壓最多、下降時慢慢回來，落地時剛好回到 0。可用起跳速度和重力算預計滯空時間 `T = 2 × vy / g`，`off = -MAX × k × sin(π × min(1, a.t / T))`。中間手（MB）滯空較久也要照自己的 `g` 算。
   - 落地（`vbAirStep` 裡 `walk.air = null` 那行）或任何把 `walk.air` 清掉的地方（`vbStop`、換位、重置等），如果還有剩下的 `camOff` 沒還，要還回去，不能讓鏡頭留在往下看的角度。
   - 加完後 `walk.pitch` 仍要在 -1.2～1.1 之間。
   - 第一人稱、第三人稱都要有效果（第三人稱也是吃 `walk.pitch` 的話就自然有）。

4. **連線**：只改自己的鏡頭，不送網路封包、不影響別人看到的動作。

## 不要做
- 不改跳躍高度、物理、擊球判定、體力消耗數值、AI、連線、比賽規則。不改現有地面上的視角輔助（`vbCamAssist`）行為。不做手機版、觸控、搖桿。不改 `blender/`、`models/`、`settings.js`。不推送、不部署。一行程式中間的註解用 `/* */`。

## 驗收
- 新增 `tools/verify-web011.cjs`，用程式模擬檢查：
  1. 體力滿起跳攻擊：最高點附近 pitch 比起跳前低約 0.21（±0.03）。
  2. 體力低（`tired` 接近 0.4）：壓的量明顯比較小；「只能小跳」：完全不壓。
  3. 攔網跳、跳發球、附近沒有球：不壓。
  4. 視角輔助開關關掉：不壓。
  5. 空中模擬滑鼠往上移一段：落地後 pitch 等於「起跳前 pitch + 滑鼠移動量」，沒有殘留偏移。
  6. 落地、`vbStop` 中途清掉 `walk.air`：都沒有殘留偏移。
