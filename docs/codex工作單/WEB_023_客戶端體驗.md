# 工作單 WEB-023：當加入者（客戶端）時的腳步聲、落點提示、時機圈、球瞬移與落地不同步

建立：2026-11-13。在 `volleycourt` 的 `game-site` 分支做（目前 main＝game-site＝bcae8c8）。只做電腦版。
Codex 用量不可超過 50%；做完就停，額度快不夠時先把進度寫進報告再停。先讀 `WEB_015_報告.md`、`WEB_018_報告.md`、`WEB_020_報告.md`。

## 使用者回報（自己去別人開的房間當加入者）
1. **腳步聲**比當主機時少很多。
2. **球的落點提示**、**擊球時機的圓框**：偶爾顯示、偶爾不顯示。
3. **球很容易瞬移**；或是**自己畫面上球已經落地了，卻還在繼續飛／滾**。

## 規劃端已查到的線索（請先查證，再找出其他原因）
- 腳步聲（球鞋「吱」）只有兩處：本機玩家（gym.html 約 5755 行）與 AI（約 11050 行，在 `vmAiStep` 裡，**只有主機會跑**）。所以加入者聽不到 AI 的腳步聲；**別的真人**的腳步聲不管誰都聽不到。
- 落點提示 `VB.target` 在 `vbAssist()`（約 10102 行）：條件包含「球最近 2.5 秒內在對面場上（`b.oppT`）」、`b.rest`、`b.mine`、`b.setT`。加入者的球會被校正（`b.err`、WEB-018 的柔和修正、WEB-020 的落地對齊），這些條件可能時有時無。`vbRings()`（約 10265 行）用 `vbPredict` 畫落點。
- 接觸時機圈（約 447 行的 CSS 註解；請找出畫圈的程式）同樣可能依賴本機球的狀態或主機才有的資料（例如 `VM.poss` 只有主機有）。
- WEB-020：不是自己負責的球，本機不判碰網；落地以負責的人回報為準（`b.floorReport`），主機最多等 0.5 秒。加入者本機的球先落地時，現在可能照物理繼續彈跳、滾動，等回報才對齊，看起來就是「落地了還在繼續」。
- 球的校正：負責的人回合中每 400 ms 校正一次；離本機玩家 3 m 內用快速修正（約 0.1 秒），誤差大時看起來像瞬移。

## 要做的事
1. **找出每個症狀的實際原因**：做一個可重現的測試環境（Node 模擬兩台電腦，或 `&localnet` 兩個分頁；加入 50～150 ms 延遲與抖動），比較主機與加入者：腳步聲次數、落點提示顯示的格數比例、時機圈顯示比例、球位置的跳動、落地時間差。原因寫進報告。
2. **腳步聲**：加入者也要聽到 AI 和別的真人的腳步聲，主機也要聽到別的真人的。用收方自己畫出來的移動（內插後的位置、速度變化）判斷急停、急轉、起跑，照本機同樣的規則播放（含距離衰減）。**不能增加任何網路訊息**。自己的腳步聲照舊。
3. **落點提示、時機圈**：加入者跟主機一樣穩定顯示。不能因為校正、球權改變、`b.oppT` 之類的狀態抖動而一下有一下沒有；需要主機才有的資料時，用已經同步的資料（`VM.tc`、`VM.remoteSetters` 等）或本機自己算。
4. **落地不同步**：別人負責的球在本機先落地時，球停在落點（不要繼續彈跳滾走），等負責的人的落地回報再對齊（照 WEB-020），超過 0.5 秒沒回報就照本機結果正常彈跳。回報的落點跟本機差很多時，平順移過去。
5. **瞬移**：把球在本機的跳動降到最低。可以調整校正頻率以外的做法（例如修正曲線、近身快速修正的條件與速度上限）；**校正訊息的頻率不能增加**。近身時本機仍要能準確接到球。
6. 主機那邊的行為不能變差。
