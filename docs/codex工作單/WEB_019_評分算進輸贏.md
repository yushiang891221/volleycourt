# 工作單 WEB-019：整場評分算進輸贏與對手、MVP 只給贏的隊

建立：2026-11-13。在 `volleycourt` 的 `game-site` 分支做，**要在 WEB-018 提交之後**。只做電腦版。
Codex 用量不可超過 50%；做完就停。

## 使用者回報
2 真人＋AI 打 6 人制，被對面 AI **0:2 打爆**，結算面板上我們隊評分卻很高：使用者 84 分 A＋MVP（自己 0 分、15 助攻、20 接球、86 碰球、15 失誤），「得分貢獻」100、隊友 80 分 A。對面 AI 都只有 B～C。使用者覺得不對，已同意下面的改法。

## 原因（規劃端已查，`gym.html` 的 `vmRateMatch()`，約 10060 行）
- 得分貢獻：`(得分＋助攻×0.5＋救球＋好接球×0.2) / 自己隊伍得分 × 隊伍人數 × 50`。輸球的隊伍總分少，比例反而高 → 滿分。
- 參與度只跟隊友比；效率 `1 − 1.5×失誤／碰球`。`e`（失誤）在 `vmPerfPoint()` 就是「最後一下是我、結果我們失分」，也就是**每一次都直接送對手一分**。
- 完全沒有算輸贏、比分差；MVP＝全場最高分，輸的隊也能拿。

## 要改的（使用者已同意）
1. **得分貢獻改成跟全場比**：分母改成「兩隊總得分 ／（兩隊總人數）」＝全場每人平均；跟全場平均一樣＝50，兩倍＝100。分子不變。
2. **新增「比賽結果」**：
   - s＝這隊在整場（所有局）拿到的分數 ／ 兩隊總分。
   - 贏：`clamp(65 + (s − 0.5) × 140, 65, 100)`；輸：`clamp(45 − (0.5 − s) × 150, 0, 45)`。
   - 權重改成：得分貢獻 30%、效率 20%、參與度 15%、位置表現 20%、比賽結果 15%。
3. **失誤加重**：效率改成 `1 − 2.5 × 失誤／碰球`（失誤＝直接讓對手得分）。
4. **MVP 只從贏的隊選**（贏隊最高分）。輸的隊最高分的人標成「**敗方最佳**」（面板上一個不同顏色的小標籤，不加經驗倍率）。伺服器那邊 MVP 經驗 ×1.1 照舊，只是 MVP 的人改了；不要改 SQL。
5. **結算面板**（`match-result.js`）：
   - 長條圖加「比賽結果 15%」，其他比重文字更新。
   - 解說文字：新增比賽結果相關的句子（例如輸球時「這場輸了，整隊評分會往下修；多拿分、少送分就會回來」，贏球分差大時誇一句），沿用現有語氣。
   - 「敗方最佳」標籤顯示在自己的標題（如果是自己）和排名列表。
   - 六角圖不改。
6. 練習模式／沒有完整比分時照舊不顯示或不記（照現有邏輯）。
